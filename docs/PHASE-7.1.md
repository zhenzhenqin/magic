# FoodDiary 阶段 7.1 部署准备与安全验证

## 一、阶段 6 遗留问题修复

新增共享权限时服务端比较所有者当前本地日期和固定的实际起点。即使旧范围曾选择「从今天开始」，只要起点已经过去，新增原照片、贴纸、营养或备注就需要确认具体起点。用户也可以把全部共享项收窄到今天。继续校验关系 ID 和版本。后端四组测试覆盖 11 月 1 日至 11 月 28 日及错误日期确认。

网络恢复和切回前台时重新读取授权，停止隐藏或断网时的轮询。新增浏览器测试覆盖断网期间撤销、恢复后立即拒绝、后台中止旧图请求和返回前台后读取替换图。沿用阶段 5、6 的纸页布局和品牌。本轮界面改动集中在共享确认及状态。

## 三、技术选型

采用 Nginx、Vue 静态构建、单进程 FastAPI/Uvicorn、SQLite WAL、私有本地媒体和 systemd。贴纸与识别用独立 Worker。Docker 可隔离受支持的 Python 运行时，但宿主机的安全维护仍需解决。推荐先确认受支持的宿主系统与变更窗口，再决定原生部署。 [生产架构](DEPLOYMENT.md)

## 四、生产配置与安全

生产拒绝 HTTP 浏览器来源、相对数据库和媒体路径及 Fake Provider。注册默认由后端关闭。内测账号使用本机交互命令创建。验收覆盖 Secure、HttpOnly、SameSite=Strict、精确 Origin、浏览器标记、Bearer 隔离、图片鉴权和 API `no-store`。单 API 进程保持限流一致。模板将上传请求设为 10 MiB + 128 KiB，应用继续做实际字节、格式、像素和磁盘校验。Nginx 配置和 Python 日志使用独立站点及 systemd 范围。

## 五、HTTPS 与域名

已有域名优先。没有域名时，Let's Encrypt 技术上支持公网 IPv4 六天证书，Webroot 使用 Certbot 5.4 或以上，需要可验证的 ACME 通路和可靠续签。也可评估已有受控私网和可信证书。在确认节点地域及云厂商规则前不开放。中国大陆节点按接入商要求核查备案或接入，IP 方式也需核查。 [IP 证书官方说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot) · [华为云备案说明](https://support.huaweicloud.com/icp_faq/icp_05_0145.html)

## 六、模型许可与 Linux 兼容性

现有 `u2netp.onnx` 的 SHA-256 为 `309c8469258dda742793dce0ebea8e6dd393174f89934733ecc8b14c76f4ddd8`，与项目校验值及 rembg 发布来源一致。上游 U-2-Net 仓库使用 Apache-2.0。现有可查资料未明确说明这个 ONNX 发布资产及训练权重的独立部署许可，因此发布产物排除权重，公网贴纸功能默认关闭。 [U-2-Net 许可](https://github.com/xuebinqin/U-2-Net/blob/master/LICENSE) · [rembg 权重来源](https://github.com/danielgatis/rembg#models)

PyPI 元数据确认 Linux x86_64 CPython 3.13 的 ONNX Runtime 1.26.0、NumPy 2.4.1 和 Pillow 13.0.0 提供 glibc 2.27/2.28 wheel。Pydantic Core、CFFI、Greenlet 和 Argon2 C 扩展也提供适用 Linux wheel。系统 Python 3.9.2 低于这些锁版本的最低要求。本地 WSL Ubuntu 用于代理验证，本地 Windows 使用真实 CPU Worker 恢复得出功能证据。服务器 Linux 实际模型加载、内存峰值、CPU 和 API 延迟留待 7.2。 [ONNX Runtime](https://pypi.org/project/onnxruntime/1.26.0/#files) · [NumPy](https://pypi.org/project/numpy/2.4.1/#files) · [Pillow](https://pypi.org/project/pillow/13.0.0/#files)

## 七、备份恢复演练

D 盘隔离环境使用已提交 WAL 的 SQLite 和五种真实媒体文件创建快照。经 `integrity_check`、`foreign_key_check` 和 SHA-256 验证，五份恢复文件与原数据逐字节一致。旧账号可以重新登录，保留旧用餐记录、好友关系、原快照的授权资料及模拟测试账本累计值。安全恢复副本撤销旧令牌和 Cookie，关闭历史授出权限，经所有者重新确认后可以再次共享。篡改媒体、空间不足和已有目的地均拒绝生成恢复副本。

演练模拟了迁移写入部分 DDL 后失败，线上路径的旧库字节及旧 revision 保持一致。单独候选随后成功升级到 `0008_friend_sharing` 并通过模型一致性检查。生产激活和停服流程只验证准备及脚本语法，不代表真实机已演练。 [恢复操作](BACKUP-RESTORE.md)

## 八、长期磁盘容量

从阶段 6 的 17 组真实本地派生取文件实际大小。平均每张原图 120,790 B，原图缩略图 24,772 B，透明抠图 274,688 B，白边贴纸 270,407 B，贴纸缩略图 137,488 B。平均五份合计 828,144 B，最大样本 997,284 B。阶段 5 的 24 组较低，平均 532,046 B。本估算采用较高的阶段 6 平均值。数据库和 WAL 每份预留 128 MiB，未假设媒体压缩收益。

| 两人每人每天三张 | 一年 | 三年 |
| --- | ---: | ---: |
| 图数 | 2,190 | 6,570 |
| 媒体平均占用 | 1.69 GiB | 5.07 GiB |
| 按本机最大样本估算 | 2.03 GiB | 6.10 GiB |
| 线上数据加七份完整日备份 | 14.51 GiB | 41.54 GiB |
| 再加四份完整周备份 | 21.77 GiB | 62.31 GiB |

当前根分区 26 GiB 可用。另应保留至少 2 GiB 备份余量、0.5 GiB 媒体保留线，并留给系统日志与暂存空间。三年场景需要离机备份或调整备份策略。1000 个资源槽在每张计入四槽时约 83 天触顶。按测得平均值，200 MiB 也会在约 84 天达到。单人一年约 865 MiB 及 4380 槽。实际测量确认后可评估 1.25 GiB / 5000 槽作为一年档，本轮保留当前配置。
