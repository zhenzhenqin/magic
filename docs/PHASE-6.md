# FoodDiary 阶段 6 交付报告

## 一、阶段完成情况

真实 API 模式新增饭搭子、好友申请、可撤销的单向共享、好友手账、月历、图鉴和双人手账。沿用阶段 5 的黑白纸页、手写字和真实食物贴纸。手动记录、识别、个人图鉴和贴纸 Worker 保留原有入口。

## 二、阶段 5 遗留问题修复结果

- 将好友媒体从本人 `PrivatePhoto` 的贴纸缺失回退流程中分出，改用只读取明确授权用途的 `SharedPhoto`。
- 图鉴的首次、最近、次数、明细、分类、封面、历史和总数均先使用授权日期范围过滤，排除本人图鉴偏好。
- 原图规范化上传与贴纸 Worker 共用存储余量及短期预留，覆盖在途上传临时文件、暂存图片及并发发布。

## 三、好友关系及数据授权架构

`services/friends.py` 以数据库唯一关系和短事务处理双方重复申请和并发接受。`services/sharing.py` 的 `SharingPolicy` 在同一 SQLite 读取快照中读取好友关系和授权，按各入口生成安全投影。好友数据持续读取所有者保存的餐次，双人手账按相同日期及四种餐次展示两人的记录。 [共享架构](SHARING.md)

## 四、数据库迁移及旧数据保留

`0008_friend_sharing` 在 `0007_stickers_catalog` 上新增好友申请、好友关系、方向授权、审计及媒体预留五张表。对阶段 5 实际测试库的只读备份逐表比较了 20 张旧表的行内容。4 个账号、4 个会话、24 餐、27 张媒体、24 个贴纸派生和 24 组图鉴关联完整保留。另用阶段 4.2 账本副本从 `0006_deepseek_budget` 升级，之前的识别任务、用量及 DeepSeek 1 次记录保持原值。两份升级副本的完整性检查均为 `ok`，外键问题均为 0。空库升级及 Alembic 模型一致性检查通过。

## 五、九项权限的实际生效规则

九项分别为饮食记录、食物名称及分类、原始照片、贴纸、图鉴、热量、营养成分、备注和历史。默认全部关闭。饮食记录控制手账、月历和摘要主体。图鉴能够独立开放，列表还需要名称权限。热量、营养成分和备注依赖饮食记录。图片权限互相独立。营养成分中的重量指食物重量。关闭字段从 JSON 省略，授权字段可分别显示未知、零和包含照片估算或调整的数据。 [完整规则](SHARING.md)

## 六、历史记录过滤及图鉴统计规则

起点按授出账号所在时区确定，并使用保存的用餐本地日期过滤。支持从当天开始、最近七天、最近三十天及全部历史。日期固定，重启和跨日无须重新计算。重新开启宽泛历史、或给现有较宽历史新增可见项目时需要明确选择。好友图鉴根据范围内的用餐记录分组，同餐多个食物共用封面时会标明整餐照片。

## 七、原始照片、贴纸及缩略图安全控制

共享媒体接口要求有效会话、好友关系、方向授权、正确媒体类型、实际归属及一个当前有效的餐次或图鉴上下文。原图、原缩略图、贴纸和贴纸缩略图分别校验，透明 cutout 保持本人访问。移除图片关联、删除餐次、活跃识别引用和撤销都会影响后续访问。私有媒体响应标记 `no-store`。

## 八、单向共享及撤销机制

接受申请之后双方仍不共享。所有者可停止向指定好友共享，解除关系同时失效两边授权，重新建立有新的关系 ID。版本检查阻止旧页面覆盖并发设置。服务端撤销提交后，新请求立即应用。已经传输的内容、设备下载和截图可能保留在对方设备。

## 九、三个真实账号的隔离测试

验证账号为测试库中的山茶、小满、栗子，分别使用独立的浏览器会话与真实认证。山茶向小满开放手账、名称、贴纸及图鉴。小满打开手账后由轮询读到山茶新保存的本地真实贴纸。栗子访问同一餐次、贴纸、月历与图鉴均返回 404。撤销后小满的旧贴纸地址返回 404，旧 Object URL 无法读取。切换到栗子后共享页面仍不可读。

## 十、自动同步及并发测试

共享页面在前台联网时每 25 秒读取，日期、焦点、网络恢复和手动按钮也会触发读取。状态失效时取消在途请求并释放图片 Object URL。后端测试同一对用户交叉发出申请、重复接受、两个窗口提交授权版本、撤销与读取竞争以及同一盘空间并发竞争。

## 十三、本地性能及查询开销

在本机 Windows 与文件 SQLite 上，用 FastAPI TestClient 和 SQLAlchemy 事件统计。每项预热一次，随后测量 30 次。SQL 总数包含一个用于共享一致性的 `BEGIN`，浏览器和图片解码耗时未计入。测量时同一授权页包含照片引用和已授权营养字段。

| 项目 | SQL 总数 / SELECT 数 | 中位数 | P95 |
| --- | --- | --- | --- |
| 好友手账 1 餐 | 9 / 8 | 34.61 ms | 45.46 ms |
| 好友手账 20 餐 | 9 / 8 | 40.82 ms | 57.09 ms |
| 好友月历 | 7 / 6 | 30.30 ms | 35.20 ms |
| 好友图鉴 21 项 | 9 / 8 | 57.27 ms | 90.58 ms |
| 好友每日摘要 | 7 / 6 | 31.57 ms | 41.44 ms |

查询数随页内餐数保持稳定。长期历史较大时，图鉴查询仍需要对授权日期范围做分组计算。真实低内存服务器的负载、长时间运行和数据库配置留到部署前验证。

## 十五、实际启动和体验方式

从项目根执行下面的命令。普通模式可以体验文字和原图共享。开启贴纸需要现有的 D 盘贴纸 Worker 环境。

```powershell
.\scripts\setup-backend.ps1 -Action Migrate
.\scripts\start-dev.ps1 -WithStickerWorker
```

打开本地前端，使用两个独立浏览器会话注册。双方从「饭搭子」复制和填写公开 ID，接受申请，选择并保存一侧的共享范围。读者可在「查看手账」「查看图鉴」和「双人手账」核对哪些内容已经开放。
