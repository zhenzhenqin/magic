# FoodDiary 饭搭子与共享

## 好友关系

登录后在「饭搭子」复制自己的公开 ID，或用好友的完整 ID 查找并发送申请。查找只返回昵称与公开 ID。自己的 ID 无法发申请。发出者可以取消，接收者可以接受或拒绝。交叉或重复发送归并为同一条待处理申请，仍由接收方明确接受。已处理的申请保留用于查看近期状态，30 天后不在列表展示，发新申请时清理过期行。

接受建立双向好友关系，九项共享权限仍全部关闭。双方只修改各自授给对方的方向。权限保存和停止共享检查关系 ID 与版本。重复删除已解除的关系保持幂等。重新建立关系会生成新 ID，旧申请所建立的共享范围和旧编辑表单不会沿用。

## 权限与字段

| 开关 | 入口和可见字段 |
| --- | --- |
| 饮食记录 | 开启手账主体、餐次和日期时间、月历、每日摘要。双人手账中的好友部分采用同一规则 |
| 食物名称及分类 | 手账中的食物名称和分类，也允许独立开启的图鉴列出食物 |
| 原始食物照片 | 授权上下文中的规范化原图和原图缩略图 |
| 美食贴纸 | 授权上下文中已生成的白边贴纸和贴纸缩略图 |
| 美食图鉴 | 独立的图鉴入口。食物名称权限关闭时，图鉴没有条目、分类或总数 |
| 热量数据 | 仅在饮食记录开放时提供热量明细和每日摘要 |
| 营养成分 | 仅在饮食记录开放时提供食物重量、蛋白质、碳水和脂肪。食物重量是用餐明细 |
| 文字备注 | 仅在饮食记录开放时提供餐次及食物明细备注 |
| 历史记录 | 允许选择更早的用餐日期作为边界，并在图鉴中读取授权范围内的历史、食用餐数、明细数和起止日期 |

名称、照片、贴纸与历史需有手账或图鉴作为数据入口。各入口也有自己的额外条件，例如图鉴读取媒体需要图鉴、食物名称及对应的图片授权。系统以专用响应结构省略未授予的字段。已授权的未知量返回 `null`，已确认的零值返回 0。每日摘要显示已知项小计、完整性，以及是否含照片估算或人工调整。共享响应排除用户体重、个人目标、登录资料、设置、模型候选和费用。

## 历史日期

首次授予以所有者设置中的 IANA 时区确定当天。选择七天时起点为当天前六天，选择三十天时为当天前二十九天，全部历史没有最早日期限制。条件包含起点当天较早的记录，按保存的用餐本地日期计算。起点写入数据库，跨午夜或月、年变化时保持原值。更改用餐日期会立即改变有效范围。双方对照使用同一个日历日期标签，各自使用原记录的用餐本地日期。

用户主动选择更早范围时需要确认。每次给过去日期新增共享项时，按实际保存的起点判断，包含更早填写的「从今天开始」授权。用户可确认沿用确切起点，或者将全部共享项收窄到当天。普通字段变更沿用当前固定边界。关闭历史会收窄较早范围，全部停止共享后再开始以当日为默认边界。

好友图鉴先过滤用餐记录，再按标准名称分组合计。名称、分类、次数、首末日期、封面候选、历史和分页都基于同一个范围。本人自定义的名称、合并、收藏、手选封面等属性不进入投影。同一餐有多个食物时，整餐照片以整餐标记显示。

## 媒体与撤销

每个共享媒体请求校验当前会话、好友关系、授出方向、指定类型、媒体归属及当前有效的记录引用。调用方必须提供唯一的 `meal_id` 或 `catalog_id`，服务端核对目标范围。删除记录或更换图片后按最新关联判断。同一图片有其他有效授权关联时，可在该关联的上下文中继续读取。

仅授予贴纸时，原图、原图缩略图、透明 cutout 及用户本人接口均不可用。贴纸缺失时显示不可用占位，原图权限沿用独立规则。尚未保存的草稿与有活跃识别任务引用的图片不进入共享投影。所有私有媒体读请求用 Bearer 认证及 `Cache-Control: no-store`。

每次请求以服务端当前状态判断权限。提交撤销后，新发起的请求立即受限。已经下载到设备的图片、截图和已在传输的内容可能仍可查看。前端对象 URL 在重新验证、路由切换、断网、页面转入后台或退出账号时释放。

## 自动同步

进入页面、切换日期、手动刷新、焦点返回和网络恢复时重新查询。页面前台在线时每 25 秒刷新。离开页面或浏览器切入后台后停止轮询。页面不持久化好友餐次或图片。共享与本人饮食使用同一数据源，保存、编辑与删除在好友下一次读取时体现。

## 验证

后端覆盖重复和交叉申请、角色校验、默认关闭、方向隔离、版本竞争、撤销、固定日期边界、图鉴裁剪、媒体关联及空间竞争。浏览器用三个独立会话验证从申请到解除，以及撤销后旧媒体地址和 Blob 失效。实际运行、测试数量及截图见[阶段 6 报告](PHASE-6.md)。
